# «Поехали»: каршеринг на микросервисах

Архитектурная документация, часть 1, без кода. Диаграммы написаны на Mermaid, GitHub и GitLab показывают их прямо в `.md`. Все диаграммы дополнительно лежат в [diagrams/](diagrams/README.md) в виде SVG, их удобно открывать отдельно и приближать. Контракты описаны в YAML, их можно открыть в Swagger Editor или AsyncAPI Studio.

## Предметная область

Пользователь находит машину на карте, бронирует её (20 минут бесплатно), открывает телефоном, едет и завершает поездку. Деньги списываются по факту: поминутно, по тарифу, который зафиксирован в момент бронирования.

**Что нельзя потерять или задвоить:**

| Инвариант | Почему критично | Кто гарантирует |
|---|---|---|
| У машины не больше одной активной аренды | Два пользователя приходят к одной машине, и компания теряет доверие клиентов | Fleet Service: условное обновление статуса машины |
| Каждая завершённая поездка оплачивается ровно один раз | Двойное списание приводит к жалобам и возвратам, пропущенное означает прямые убытки | Billing Service: идемпотентность по `rentalId` и ключ идемпотентности у PSP |
| Предавторизация (hold) снимается с карты после отмены | Иначе деньги клиента заморожены без причины | Сага аренды: компенсация `ReleaseHold` |
| Машина не остаётся открытой без активной поездки | Угон или порча, страховой случай | Сага аренды: компенсация `LockCar` |

**Процесс, который может сломаться посередине:** аренда. Это распределённая сага, в которой участвуют машина с IoT-блоком (бывает без связи), внешний платёжный шлюз (бывает с таймаутами) и несколько наших сервисов. Шаги растянуты на минуты и часы, поэтому уложить их в одну ACID-транзакцию нельзя.

## Сервисы

| Сервис | Коротко | Хранилище |
|---|---|---|
| **User Service** | Профиль водителя, допуск к вождению, флаг долга | PostgreSQL |
| **Fleet Service** | Автопарк: машины, статус, координаты, топливо, поиск рядом | PostgreSQL + PostGIS |
| **Rental Service** | Жизненный цикл аренды, оркестратор саги | PostgreSQL |
| **Telematics Gateway** | Адаптер к IoT-блокам машин: команды open/lock, телеметрия | PostgreSQL |
| **Billing Service** | Тарифы, расчёт стоимости, hold/capture/refund через PSP, долги | PostgreSQL |
| **Notification Service** | Push, SMS, email: чеки и статусы | PostgreSQL (журнал отправок) |

Инфраструктура: API Gateway (аутентификация по JWT, rate limiting), брокер Apache Kafka, Identity Provider (Keycloak).

## Предлагаемое разделение в команде (3-4 человека)

| Участник | Зона ответственности |
|---|---|
| 1 | Rental Service (сага), Kafka-инфраструктура, outbox-библиотека |
| 2 | Billing Service и мок PSP |
| 3 | Fleet Service и Telematics Gateway с симулятором машин |
| 4 | User Service, Notification Service, API Gateway, docker-compose, наблюдаемость |

Если в команде три человека, четвёртую зону делят между вторым и третьим участником.

## Глоссарий

| Термин | Значение |
|---|---|
| **Аренда (Rental)** | Весь путь от бронирования до закрытия расчёта, агрегат Rental Service |
| **Бронь** | Аренда в статусе `RESERVED`: машина закреплена за пользователем, 20 минут бесплатно |
| **Поездка** | Аренда в статусе `ACTIVE`: машина открыта, идёт поминутная тарификация |
| **Hold (предавторизация)** | Блокировка суммы на карте без списания |
| **Capture** | Списание ранее заблокированной суммы (полностью или частично) |
| **Void** | Отмена hold без списания |
| **PSP** | Payment Service Provider, внешний платёжный шлюз |
| **Телематический блок** | IoT-устройство в машине: открывает и закрывает её, передаёт GPS, пробег и уровень топлива |
| **Сага** | Последовательность локальных транзакций с компенсациями вместо распределённой транзакции |
